# Semantic conventions for Generative AI events

**Status**: [Development][DocumentStatus]

- [Event: `gen_ai.guardrail.result`](#event-gen_aiguardrailresult)

GenAI instrumentations MAY capture user inputs sent to the model and responses received from it as [events](https://github.com/open-telemetry/opentelemetry-specification/blob/v1.55.0/specification/logs/data-model.md#events).

> [!Note]
> Events are in-development and not yet available in some languages. Check [spec-compliance matrix](https://github.com/open-telemetry/opentelemetry-specification/blob/v1.55.0/spec-compliance-matrix.md#logs) to see the implementation status in corresponding language.

For events describing inference operations, see [Client Inference](client-inference.md#events).

The event name MUST be `gen_ai.evaluation.result`.

This event captures the result of evaluating GenAI output for quality, accuracy, or other characteristics. This event SHOULD be parented to GenAI operation span being evaluated when possible or set `gen_ai.response.id` when span id is not available.

**[1] `error.type`:** The `error.type` SHOULD match the error code returned by the Generative AI provider or the client library,
the canonical name of exception that occurred, or another low-cardinality error identifier.
Instrumentations SHOULD document the list of errors they report.

**[2] `gen_ai.evaluation.score.label`:** This attribute provides a human-readable interpretation of the evaluation score produced by an evaluator. For example, a score value of 1 could mean "relevant" in one evaluation system and "not relevant" in another, depending on the scoring range and evaluator. The label SHOULD have low cardinality. Possible values depend on the evaluation metric and evaluator used; implementations SHOULD document the possible values.

**[3] `gen_ai.response.id`:** The unique identifier assigned to the specific
completion being evaluated. This attribute helps correlate the evaluation
event with the corresponding operation when span id is not available.

**Status:** ![Development](https://img.shields.io/badge/-development-blue)

The event name MUST be `gen_ai.guardrail.result`.

Describes a result produced by a guardrail.

This event SHOULD be emitted for results returned by remote guardrail
services and dedicated in-process guardrail APIs.

A guardrail operation MAY emit multiple result events when the API reports
multiple categories, filters, or checks. Instrumentations MUST preserve
provider-native result values and MUST NOT infer an allow or deny verdict
from scores or categories.

**[1] `error.type`:** The `error.type` SHOULD match the error code returned by the Generative AI provider or the client library,
the canonical name of exception that occurred, or another low-cardinality error identifier.
Instrumentations SHOULD document the list of errors they report.

**[2] `gen_ai.guardrail.policy.id`:** If the guardrail API accepts or reports a policy identifier.

**[3] `gen_ai.guardrail.policy.version`:** If the guardrail API accepts or reports a policy version.

**[4] `gen_ai.guardrail.result.type`:** If the guardrail API reports a named result field or result kind.

**[5] `gen_ai.guardrail.result.type`:** This identifies the result field or result kind reported by the instrumented guardrail API. Instrumentations MUST NOT translate it into a generalized allow or deny verdict.

**[6] `gen_ai.guardrail.result.value`:** Instrumentations SHOULD preserve the value reported by the guardrail API. Non-string primitive values SHOULD be converted to their canonical string representation.

**[7] `gen_ai.guardrail.risk.category`:** Instrumentations SHOULD preserve the category reported by the guardrail API and MUST NOT translate it to a different taxonomy.

**[8] `gen_ai.guardrail.risk.score`:** If the guardrail API reports a risk, confidence, or severity score.

**[9] `gen_ai.guardrail.risk.score`:** Instrumentations SHOULD preserve the score reported by the guardrail API and document its scale.

**[10] `gen_ai.guardrail.source`:** If the guardrail API reports the source or stage of the evaluated content.

**[11] `gen_ai.guardrail.source`:** Instrumentations SHOULD preserve the value reported by the guardrail API. For APIs that express the source through the operation being called, instrumentations SHOULD use that operation's source term.

**[12] `gen_ai.guardrail.component.name`:** This identifies the guardrail evaluation service or component, not the policy. For the policy evaluated by the guardrail, use `gen_ai.guardrail.policy.id`.

**[13] `gen_ai.guardrail.policy.rule.id`:** Use this when `gen_ai.guardrail.policy.id` identifies a broader policy and the guardrail reports a more specific rule, filter, or detector.

**[14] `gen_ai.guardrail.result.reason`:** The value SHOULD be low-cardinality and MUST NOT contain sensitive user content or other high-risk data.

**[15] `gen_ai.provider.name`:** Semantic conventions for individual GenAI operations SHOULD clarify which
kinds of providers (e.g. inference, embeddings, retrieval, memory, hosted
agent providers) apply when it is not clear from context.

The attribute SHOULD be set based on the instrumentation's best knowledge
and may differ from the actual upstream provider. For example, a client SDK
may be configured against a proxy or hosting platform that transparently
relays requests to a different provider.

The `gen_ai.provider.name` attribute acts as a discriminator that
identifies the GenAI telemetry format flavor specific to that provider
within GenAI semantic conventions.
It SHOULD be set consistently with provider-specific attributes and signals.
For example, GenAI spans, metrics, and events related to AWS Bedrock
should have the `gen_ai.provider.name` set to `aws.bedrock` and include
applicable `aws.bedrock.*` attributes and are not expected to include
`openai.*` attributes.
