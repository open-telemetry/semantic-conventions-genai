# Semantic conventions for Generative AI events

**Status**: [Development][DocumentStatus]

<!-- toc -->

- [Event: `gen_ai.evaluation.result`](#event-gen_aievaluationresult)
- [Event: `agent.threat.detection`](#event-agentthreatdetection)

<!-- tocstop -->

GenAI instrumentations MAY capture user inputs sent to the model and responses received from it as [events](https://github.com/open-telemetry/opentelemetry-specification/blob/v1.55.0/specification/logs/data-model.md#events).
Capturing message content on events is controlled by [content capture configuration](gen-ai-spans.md#content-capture-configuration) (e.g. `OTEL_INSTRUMENTATION_GENAI_CAPTURE_CONTENT=EVENT_ONLY` or `SPAN_AND_EVENT`).

> [!Note]
> Events are in-development and not yet available in some languages. Check [spec-compliance matrix](https://github.com/open-telemetry/opentelemetry-specification/blob/v1.55.0/spec-compliance-matrix.md#logs) to see the implementation status in corresponding language.

For events describing inference operations, see [Client Inference](client-inference.md#events).

The event name MUST be `gen_ai.evaluation.result`.

This event captures the result of evaluating GenAI output for quality, accuracy, or other characteristics. This event SHOULD be parented to GenAI operation span being evaluated when possible or set `gen_ai.response.id` when span id is not available.

**[1] `error.type`:** The `error.type` SHOULD match the error code returned by the Generative AI provider or the client library,
the canonical name of exception that occurred, or another low-cardinality error identifier.
Instrumentations SHOULD document the list of errors they report.

**[2] `gen_ai.evaluation.score.label`:** This attribute provides a human-readable interpretation of the evaluation score produced by an evaluator. For example, a score value of 1 could mean "relevant" in one evaluation system and "not relevant" in another, depending on the scoring range and evaluator. The label SHOULD have low cardinality. Possible values depend on the evaluation metric and evaluator used; implementations SHOULD document the possible values.

**[3] `gen_ai.response.id`:** The unique identifier assigned to the specific
completion being evaluated. This attribute helps correlate the evaluation
event with the corresponding operation when span id is not available.

## Event: `agent.threat.detection`

**Status:** ![Development](https://img.shields.io/badge/-development-blue)

The event name MUST be `agent.threat.detection`.

A single threat-detection decision recorded against an agent operation.

A single operation MAY produce multiple `agent.threat.detection` events. For example, the same `execute_tool` operation can produce one request-side network/control finding and one response-side content finding. Modeling each finding as its own event keeps the parent span lean and avoids cramming flat span-level attributes for repeated detections.
This event SHOULD be parented to the agent operation span being evaluated (`gen_ai.invoke_agent`, `gen_ai.execute_tool`, etc.) or to a separately-scoped enforcement span owned by the detection layer when the detection happened outside a provider span (e.g. forward proxy, MCP proxy, CI wrapper).
Instrumentations SHOULD set the severity number according to `agent.threat.detection.severity`: low -> 9 (INFO), medium -> 13 (WARN), high and critical -> 17 (ERROR). A detection, including a blocked one, is not an application or system failure, so instrumentations SHOULD NOT record this event with a FATAL severity. The criticality of the matched rule is carried by `agent.threat.detection.severity`.

**Requirement level:** [Recommended](https://github.com/open-telemetry/semantic-conventions/blob/v1.45.0/docs/general/signal-requirement-level.md).

**Attributes:**

| Key | Stability | [Requirement Level](https://opentelemetry.io/docs/specs/semconv/general/attribute-requirement-level/) | Value Type | Description | Example Values |
| --- | --- | --- | --- | --- | --- |
| [`agent.threat.detection.action`](/docs/registry/attributes/agent.md) | ![Development](https://img.shields.io/badge/-development-blue) | `Required` | string | Enforcement decision taken at detection time. [1] | `allow`; `block`; `warn` |
| [`agent.threat.detection.rule_id`](/docs/registry/attributes/agent.md) | ![Development](https://img.shields.io/badge/-development-blue) | `Required` | string | Stable identifier of the detection rule that fired, scoped by `agent.threat.detection.ruleset`. [2] | `ATR-2026-00440`; `pipelock.network.egress.deny-cloud-metadata`; `acme.policy.allowlist.tool-call` |
| [`agent.threat.detection.ruleset`](/docs/registry/attributes/agent.md) | ![Development](https://img.shields.io/badge/-development-blue) | `Required` | string | Stable namespace and version of the ruleset that issued the rule, in `<namespace>@<version>` form. [3] | `atr@v2.2.1`; `pipelock-rules@2026.05`; `vendor-x-bundle@2025.10`; `local-policy@deploy-123` |
| [`agent.threat.detection.severity`](/docs/registry/attributes/agent.md) | ![Development](https://img.shields.io/badge/-development-blue) | `Required` | string | Severity assigned by the ruleset to the matched rule. [4] | `low`; `medium`; `high` |
| [`agent.threat.detection.correlation_id`](/docs/registry/attributes/agent.md) | ![Development](https://img.shields.io/badge/-development-blue) | `Recommended` | string | Opaque producer-defined identifier that joins this span/event to richer audit context held outside telemetry. [5] | `pipelock-receipt-01HZ1V4SX5`; `atr-scan-uuid-9e4f`; `audit-packet:sha256:9bf3...` |

**[1] `agent.threat.detection.action`:** `action` describes the decision at the detection point, not the eventual resolution of an approval flow. When an `ask` decision is later resolved by a human or external system to `allow` or `block`, the resolution SHOULD be recorded as a separate event or span rather than overwriting this attribute.

**[2] `agent.threat.detection.rule_id`:** Rule identifiers are opaque strings owned by the ruleset author. Consumers MUST NOT attempt to parse meaning from the identifier shape; `agent.threat.detection.ruleset` is the only namespace anchor.

**[3] `agent.threat.detection.ruleset`:** The namespace is intentionally open-set. Open detection-rule libraries, vendor proprietary bundles, and locally-authored policy packs are peers in this convention. Consumers MUST NOT hardcode a particular ruleset prefix.

**[4] `agent.threat.detection.severity`:** Severity is a property of the rule itself, not the enforcement decision. A `high` rule may still result in `agent.threat.detection.action=allow` under a permissive policy, and a `low` rule may result in `block` under a strict policy.

**[5] `agent.threat.detection.correlation_id`:** The value is opaque to this convention. Producers SHOULD use it to join to signed receipts, audit packets, OTLP trace IDs, or vendor-specific evidence stores without putting the underlying prompts, tool arguments, or business payloads directly into the span or event.
This attribute is intended for span and log/event use; it has unbounded cardinality and SHOULD NOT be used as a metric label.

---

`agent.threat.detection.action` has the following list of well-known values. If one of them applies, then the respective value MUST be used; otherwise, a custom value MAY be used.

| Value | Description | Stability |
| --- | --- | --- |
| `allow` | Operation was permitted to proceed. | ![Development](https://img.shields.io/badge/-development-blue) |
| `ask` | Operation paused for human or external approval. The absence of execution is intentional and successful, not a missing span or generic error. | ![Development](https://img.shields.io/badge/-development-blue) |
| `block` | Operation was denied. | ![Development](https://img.shields.io/badge/-development-blue) |
| `warn` | Operation proceeded; a concern was recorded for downstream review. | ![Development](https://img.shields.io/badge/-development-blue) |

---

`agent.threat.detection.severity` has the following list of well-known values. If one of them applies, then the respective value MUST be used; otherwise, a custom value MAY be used.

| Value | Description | Stability |
| --- | --- | --- |
| `critical` | Confirmed abuse pattern; warrants immediate enforcement. | ![Development](https://img.shields.io/badge/-development-blue) |
| `high` | Likely abuse; warrants blocking or approval routing in most policies. | ![Development](https://img.shields.io/badge/-development-blue) |
| `low` | Informational; no immediate enforcement implication. | ![Development](https://img.shields.io/badge/-development-blue) |
| `medium` | Notable; warrants log review or rate gating. | ![Development](https://img.shields.io/badge/-development-blue) |
