Guardrails evaluate GenAI content before or after a GenAI operation. These
conventions cover remote guardrail services and dedicated in-process guardrail
APIs.

Use a `gen_ai.apply_guardrail.client` span for a request to a remote guardrail
service. Emit `gen_ai.guardrail.result` events for results returned by remote
services or dedicated in-process guardrail APIs.

General-purpose hooks, callbacks, and middleware are not sufficient evidence
that an operation is a guardrail. Instrumentation MUST NOT classify one as a
guardrail unless the instrumented library exposes dedicated guardrail semantics.

For the systems surveyed while defining these conventions, see
[Evaluated guardrail systems](non-normative/gen-ai-guardrail-systems.md).

## Guardrail concepts

- **Guardrail component**: the service or dedicated API performing the
  evaluation, identified by `gen_ai.guardrail.component.name`.
- **Policy**: the policy or configuration evaluated by the guardrail,
  identified by `gen_ai.guardrail.policy.*`.
- **Result**: the provider-native result field and value reported by the
  guardrail, identified by `gen_ai.guardrail.result.*`.
- **Source**: the provider-native source or stage of the evaluated content,
  identified by `gen_ai.guardrail.source`.
- **Risk**: a provider-native category and score reported for an individual
  result, identified by `gen_ai.guardrail.risk.*`.

Instrumentations MUST preserve provider-native result, source, category, and
score values. They MUST NOT infer a generalized allow or deny verdict from a
severity, match, category, or service intervention result.

## Examples

The following non-normative examples illustrate how provider-native request and
response fields map to these conventions.

### Amazon Bedrock Guardrails

For `ApplyGuardrail`, the client span wraps the SDK operation. The request
provides the guardrail identifier, version, and `source`. The response provides
the native `action`, optional `actionReason`, output content, and assessments.

```text
apply_guardrail Amazon Bedrock Guardrails (CLIENT)
  gen_ai.operation.name = "apply_guardrail"
  gen_ai.provider.name = "aws.bedrock"
  gen_ai.guardrail.component.name = "Amazon Bedrock Guardrails"
  gen_ai.guardrail.policy.id = <guardrailIdentifier>
  gen_ai.guardrail.policy.version = <guardrailVersion>
  gen_ai.guardrail.source = <source>
  gen_ai.guardrail.result.type = "action"
  gen_ai.guardrail.result.value = <response.action>
  gen_ai.guardrail.result.reason = <response.actionReason>
```

One or more `gen_ai.guardrail.result` events can describe the response
assessments using their native filter or category names.

### Azure AI Content Safety

For `analyze_text`, the client span wraps the SDK operation. Azure returns
per-category severity values but no overall verdict or caller action. Emit one
result event per returned category and do not derive allow or deny from the
severity.

```text
gen_ai.guardrail.result
  gen_ai.guardrail.component.name = "Azure AI Content Safety"
  gen_ai.provider.name = "azure.ai.content_safety"
  gen_ai.guardrail.result.type = "severity"
  gen_ai.guardrail.result.value = <category.severity as a string>
  gen_ai.guardrail.risk.category = <category.category>
  gen_ai.guardrail.risk.score = <category.severity>
```

### OpenAI Agents

OpenAI Agents exposes dedicated input, output, tool-input, and tool-output
guardrail APIs. Instrumentation can emit a result event from the guardrail
result object without creating an internal span.

```text
gen_ai.guardrail.result
  gen_ai.guardrail.component.name = <guardrail name>
  gen_ai.guardrail.source = <input, output, tool_input, or tool_output>
  gen_ai.guardrail.result.type = "tripwire_triggered"
  gen_ai.guardrail.result.value = <tripwire_triggered as a string>
```
