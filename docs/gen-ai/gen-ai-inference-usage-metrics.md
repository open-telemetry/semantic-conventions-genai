## Token usage instruments

The conventions described in this document are specific to Generative AI client
applications and describe how inference token usage is reported.

Individual systems may include additional system-specific attributes.
It is recommended to check system-specific documentation, if available.

Two families of token usage instruments are defined:

- **Counters** (`gen_ai.client.inference.usage.detailed.*`) report how many tokens were
  spent. Each token category is a separate monotonic counter broken down by
  [`gen_ai.token.modality`](/docs/registry/attributes/gen-ai.md), so a plain
  sum of a single counter is always meaningful. The `cache_read`,
  `cache_write`, and `reasoning` counters report subsets of the `input_tokens`
  and `output_tokens` counters.
  Use counters for total token usage and rate, cost approximation, and
  breakdowns by modality.
- Per-operation **histograms** (`gen_ai.client.inference.usage.input_tokens` and `gen_ai.client.inference.usage.output_tokens`)
  describe how token usage is distributed across individual inference operations.
  Input and output are separate instruments.
  Use histograms to find outliers and to monitor the distribution of input and output
  token usage.

> [!NOTE]
> 
> The `gen_ai.client.inference.usage.input_tokens` and
> `gen_ai.client.inference.usage.output_tokens` histograms are
> deliberately not broken down by modality: percentiles across modalities do
> not add up.
> 
> A query like this one appears valid:
> 
> ```promql
> histogram_quantile(0.95,
>   sum(rate({"gen_ai.client.inference.usage.input_tokens"}[5m]))
> )
> ```
> 
> However, if modality were added as a dimension, it would produce meaningless results: for
> 100 identical operations with 300 input tokens each (100 text and 200 image),
> it would return 200 instead of 300.
> 
> For the full reasoning behind this design, see
> [Token usage metrics design](/docs/gen-ai/non-normative/usage-metrics-design.md).

may be configured against a proxy or hosting platform that transparently

The `gen_ai.provider.name` attribute acts as a discriminator that
identifies the GenAI telemetry format flavor specific to that provider
within GenAI semantic conventions.
It SHOULD be set consistently with provider-specific attributes and signals.
